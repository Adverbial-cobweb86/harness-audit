# Obsidian and agents

Obsidian is markdown on disk, so the same rules apply to every agent. What changes is where notes live and how agents reach them.

## Topologies (detected by detect.py, confirmed with the user)

| Topology | Example | docs_dir in config | Agent access | Notes |
|---|---|---|---|---|
| inside-repo | `repo/docs/` is a vault (has `.obsidian/`) | `docs` | native | Best for agents, teammates and CI. Add `.obsidian/workspace*.json` to `.gitignore`. |
| repo-inside-vault | `Vault/Projects/app/` is the git repo | the project's notes folder, relative | native | Keep notes for this project inside the repo folder; other vault areas are out of scope. |
| external | `~/Vault/Projects/App/` separate from the repo | absolute path, e.g. `~/Vault/Projects/App` | needs explicit access | Claude Code: `permissions.additionalDirectories` (installer adds it). Codex: `--add-dir`. Cursor: multi-root workspace. Git hooks and CI cannot see these notes; the hook-based checks still run locally. |

Recommendation when the user has no preference: agent-facing knowledge (decisions, architecture, runbooks, plans) in repo `docs/`, opened as its own vault or included in the main vault through a symlink from the vault to the repo (not the other way around). Personal thinking and raw sources can stay in the main vault.

## Rules for agent-facing notes
- Frontmatter: `description`, `read_when`, `status`, `updated`. Obsidian Properties and Dataview read the same fields.
- Links: use markdown links with relative paths (`[Billing](../architecture/billing.md)`). Obsidian resolves them; agents can follow them. Bare `[[wikilinks]]` are fine for humans but agents cannot resolve them reliably (lint H017). In Obsidian settings: Files and links → "Use [[Wikilinks]]" off, "New link format" relative path.
- The index is generated by `build_index.py`, never written by hand. It renders as a normal note.
- Raw sources (web clips, transcripts) go to `raw/` and are never edited; compiled notes cite them.
- PARA-style organization for humans can coexist: agents navigate through the index and `read_when`, not through folder semantics. Placement folders only need to exist inside the project's docs root.
- Never `@import` vault notes into CLAUDE.md: imports load every session.
- Attachments: keep in `_attachments/` (excluded from index and lint).

## Vault-level index (shared vault with many projects)
If one vault serves several projects, each project folder gets its own `index.md`. A vault-level `Projects.md` can link to each project index; do not make agents read it by default.
